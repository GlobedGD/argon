# v2 migration

For Geometry Dash 2.209, Argon has been changed to be a *mod* instead of a plain C++ dependency, which makes updating it a lot easier and lets us share state without hacks. This means, you'll need to remove the following lines from CMakeLists.txt of your mod:

```cmake
CPMAddPackage("gh:GlobedGD/argon@x.x.x")
target_link_libraries(${PROJECT_NAME} argon)
```

and instead add Argon as a `mod.json` dependency:

```json
"dependencies": {
    "dankmeme.argon": ">=2.0.0"
}
```

## Client-side usage

Most functions like `startAuth` or `clearToken` are unchanged, so most mods should compile fine out of the box. However, there were a few changes that are worth pointing out:

### Header change

The `argon/` subfolder is dropped and the mod ID prefix is now needed, so the new include is:
```cpp
#include <dankmeme.argon/argon.hpp>
```

### `forceStrong`

This bool has been removed from startAuth, so if you used it, you need to validate details on your server instead.

### Argon server & cert verification

Server URL and cert verification stayed semi-global settings: this means they are applied globally for your mod, but not other mods. For that, the API slightly changed:

```cpp
// use this to change the URL of the Argon server, for example for a GDPS
argon::overrideArgonServer("https://argon.mymod.com");

// use this to toggle cert verification (on by default)
argon::overrideCertVerification(false);
```

## Server-side usage

For compatibility purposes, the old `/v1/` API does stay working for some time, but you should **NOT** use it in new services. It is only guaranteed to be available in this short period where mods are still being ported. You should migrate to the new `/v2/` API as soon as possible, and it can still accept tokens generated by old (GD 2.208) clients, provided their Argon version was recent enough.

NOTE: current base URL is `https://argon-dev.globed.dev`. This is temporary, and to be changed once Geode beta is released.

### Token check endpoint

All the token check endpoints were replaced by one, singular validation endpoint. The WebSocket API has also been removed as it has been determined the single HTTP endpoint is good enough when using connection pooling and HTTP/2 or HTTP/3.

The endpoint is `POST /v2/token/validate`, and it takes a JSON body:
```json
{
    "token": "...."
}
```

If the token is invalid, this will return a 200 OK with `"valid": false`:
```json
{
    "valid": false,
    "account_data": null,
    "discord_user": null
}
```

If the token is good, this will return a 200 OK with account data:
```json
{
    "valid": true,
    "account_data": {
        "account_id": 29843187,
        "user_id": 256456125,
        "username": "globedbotxd13"
    },
    "discord_user": null
}
```

There's no `check-strong` endpoint and there is no weak validation anymore - instead, the endpoint returns full account data of the user, for you to use yourself.

### API keys

If you had an API key issued to you for better rate limits, please contact me on discord (`@dank_meme01`). The new backend supports API keys, but only on `/v2/` endpoints, and the old keys are not valid and will have to be regenerated.

### Discord linking

While not a change per se, Argon now has a centralized solution for linking GD accounts with Discord accounts. If you want to receive the data about the user's linked account, you can request it using the same endpoint, `POST /v2/token/validate`, by including `"include_discord": true`:
```json
{
    "token": "....",
    "include_discord": true
}
```

If the token is valid and the user is linked to a Discord account, the response will include a `discord_user` object:
```json
{
    "valid": true,
    "account_data": {
        "account_id": 29843187,
        "user_id": 256456125,
        "username": "globedbotxd13"
    },
    "discord_user": {
        "id": 612930885230002208,
        "username": "dank_meme01",
        "avatar_url": "https://cdn.discordapp.com/avatars/612930885230002208/7022f122ed40fa8837666706d12efc55.webp?size=1024"
    }
}
```
